# 改编工程产品需求

## 背景与第一性原理

作者持续积累的作品和判断，比某次生成的文字或界面存活更久。外部Agent擅长理解和生成，固定引用、版本、范围及文件处理适合确定性软件。重复要求模型重建结构会增加上下文和等待，但本产品不承诺固定token节省比例。

从固定原著到剧本、漫画或有声剧，维护删、并、拆、增的理由与来源映射。 需要长期专业状态和可视化审阅，适合作为按需安装的插件；核心只持有通用创作事实。

## 用户与目标

小说作者、编剧、漫画作者及音频创作者通过现有Agent对话完成准备和操作，回来检查实际成果。作者可直接编辑，但不必手工重复录入已说过的信息。

## 首版完整范围

原著单元、目标段落、改编映射、改编例外；固定读取、增量维护、检查、比较、可恢复写入、JSON/Markdown/HTML报告、专业成果导出、包内Skill及同连接热发现。

完整流程：复盘固定原著→划分来源单元→组织目标分集→比较删并拆增→准备目标候选→原著更新影响→局部返工。

## 边界与非目标

原著和改编作品各自拥有正文与设定。插件在当前作品维护专业映射；外部目标仅是固定引用，Agent必须沿目标自己的management_ref核验并创建任务。不得把当前连接当成另一端已获权，不把改编例外写回原著。未知目标修订显示待核验。

不复制宿主正文、正式设定或版本库，不建设聊天和多Agent调度，不含发布、投放和运营。专业状态和候选不等于采纳或定稿。
